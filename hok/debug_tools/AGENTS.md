# hok/debug_tools — 调试工具规范

本文件适用于 `hok/debug_tools/` 下的调试脚本、CLI、样例输入输出与临时验证材料。

## 1. 总原则

1. `debug_tools/` 只放调试、验证、演示、一次性导出与 CLI 辅助工具，不承载线上业务逻辑。
2. 新调试工具必须以独立文件夹组织；每个调试目标对应一个子文件夹，脚本、样例数据、输出文件放在该文件夹内。
3. 调试工具应最小化复用项目既有接口，不复制 `hok/` 业务实现，不绕开已有 API、IO、时间、消息发送等职责边界。
4. `debug_tools/` 下所有子文件夹默认被 `.gitignore` 忽略；需要沉淀为长期能力时，应迁移到职责明确的 `hok/tools/`、`hok/zfunc.py`、`hok/zapi.py` 等位置，并同步更新根目录 `AGENTS.md`。
5. 子目录内可以放脚本级说明，但不要在本文件记录每个函数的具体功能，只维护 CLI 规范与宏观工具索引。

## 2. CLI 规范

1. CLI 脚本优先使用 `argparse`，入口必须使用 `main()` 并通过 `if __name__ == "__main__": raise SystemExit(main())` 返回退出码。
2. CLI 必须支持 `--help`，参数名称要清晰表达输入、输出、日期范围、格式与开关含义。
3. CLI 的输入路径、输出路径、日期、用户 ID、群号、API-Key、模型名、服务地址等可变值必须通过参数或项目配置提供，不得在逻辑中硬编码环境相关值。
4. CLI 读写文件优先使用 UTF-8；若直接处理文件路径，应通过 `pathlib.Path` 或项目内 IO 接口保持路径可迁移。
5. CLI 失败必须可见：捕获异常时要输出发生位置、关键参数与 `repr(err)`，并返回非 0 退出码；禁止静默失败。
6. CLI 不应在 import 时执行请求、写文件、注册任务或改变工作目录；所有副作用必须发生在 `main()` 调用链内。
7. CLI 输出文件默认应写入调试工具自己的子目录、`data/` 下明确的导出目录，或由 `--output` 指定的位置。
8. CLI 如需访问外部 API，应明确暴露相关参数与配置来源，并避免在无用户确认的情况下执行大批量请求。
9. CLI 面向调试可直接打印结果摘要，但不要依赖 NoneBot 事件、bot 实例或消息适配器。

## 3. 现有调试工具索引

- `gametime_rank_demo/`：游戏时长排行演示工具，用于生成演示数据与排行效果验证。
- `image_gen/`：图片生成接口调试工具，用于验证 APIMart 等图片生成链路。
- `history_map_export_cli/`：历史汇总导出 CLI，用于从 `data/history/YYYY-MM-DD.json` 导出玩家每日各地图局数与胜场。
- `benefit_debug_page/`：受益受害贝叶斯收缩计算过程可视化页面模板。
- `kpl_match_collector_cli.py`：KPL 赛事采集调试入口，用于命令行验证赛事赛程、单场数据与采集适配结果；这是历史遗留的根目录 CLI，后续新增同类工具应改为独立子文件夹。
- `kpl_match_cli/`：KPL 赛程、完整比赛详情与长图生成的菜单式 CLI，直接调用 `zkpl.py` 和 `tools/gen_kpl_match_card.py`。
