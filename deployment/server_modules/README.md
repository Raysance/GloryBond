# 服务器维护

GloryBond 的 Bot 与 Web 共用一个代码检出、运行环境和私有配置，分别由 systemd 服务管理。源码发布使用根 GitHub Actions 工作流，连接与配置同步见[开发与部署说明](../../docs/DEVELOPMENT.md)。

## 职责划分

| 内容 | 管理方式 |
| --- | --- |
| 应用源码与依赖 | GloryBond 主仓库和私有 SDK 子模块 |
| 凭据、登录态与身份映射 | Git 忽略的应用配置，通过 SSH 单独同步 |
| 数据库、消息归档与运行状态 | PostgreSQL、Redis 及私有业务存储 |
| 应用进程与反向代理 | 模块服务定义及主机集成配置 |
| 备份与历史迁移材料 | 独立私有备份，按恢复需求读取 |

本目录维护 HOK 模块的管理和备份能力。共享数据库、代理、证书与其他应用按各自职责管理。

## 工具索引

| 工具 | 用途 |
| --- | --- |
| [modulectl.py](modulectl.py) | 模块状态、启停、导出与主机集成 |
| [snapshot_hok.py](snapshot_hok.py) | HOK PostgreSQL 与 Redis 业务数据快照 |
| [verify_export.py](verify_export.py) | 导出清单、文件和数据快照校验 |
| [refresh_export.py](refresh_export.py) | 补齐导出包中的维护工具，保留原始快照 |
| [sync_operations.py](sync_operations.py) | 预览或同步 HOK 维护工具，备份并移除过时入口 |

维护工具同步以预览为默认行为，显式应用时先保存恢复副本。同步范围为 HOK 维护目录，应用配置、服务定义和其他模块保持原状。一次性迁移脚本与交接记录已归档。

## 备份与恢复

- 完整导出包含应用资源、配置、数据库快照和 QQ 会话，按私有材料保存与传输。
- PostgreSQL 使用一致性转储，Redis 快照覆盖 HOK 业务命名空间并保留有效期。恢复时核对目标和冲突，保留现有有效数据。
- 需要统一静止点时使用模块导出的静止模式；操作结束后恢复原有运行状态，共享服务保持运行。
- 恢复前验证导出清单和校验值，在独立位置检查内容，再准备依赖、服务和私有配置。环境重建使用当前项目依赖清单。
- 恢复后检查成员服务、Web 健康和 QQ 连接。源码回退与私有配置恢复分别处理。
