# GloryBond (QQ-HOK-Agent) User Manual

[![GitHub](https://img.shields.io/badge/GitHub-Repository-blue?logo=github)](https://github.com/Raysance/GloryBond)

GloryBond是Bot与Web的唯一开发及部署仓库。实现、文档和部署脚本公开；用户信息、登录态和密钥保存在Git忽略的 `.env` 与 `config.yaml`。运行需要私有SDK访问授权及自己的配置，见[开发与部署说明](docs/DEVELOPMENT.md)。

源码已统一整理到 [`src/glorybond`](src/glorybond)，按应用入口、业务功能、共享 AI、外部服务、账号、存储和渲染分工。测试集中在 `tests/`，开发工具在 `tools/`，功能手册在 `docs/manual/`。目录职责与调用关系见[项目结构](docs/ARCHITECTURE.md)；现有 QQ 命令、网页地址、订阅和数据继续沿用。

项目与营地 SDK 统一使用 Python 3.13，CI 与生产环境保持一致。营地 SDK 仅运行一组完整离线测试，通过私有仓库和固定 submodule 提交更新，无需另建 GitHub Release。

阿里云搜索缺少密钥时，会明确提示应配置的环境变量名称；不会显示密钥内容。

共享代理支持每5分钟连通性检查与备用地区切换，订阅每日刷新，故障时限频提前刷新；配置校验、回滚与操作入口见[代理维护说明](deployment/server_modules/CLASH_WATCHDOG.md)。

AI 聊天直接给出判断和依据，估算随结论说明口径与关键假设，不额外堆叠“仅供参考、不是定律”等常识性免责声明；会影响答案的具体不确定性仍在相关判断旁说明。QQ 与 Web、通用助手与角色聊天沿用同一表达规则。

群命令、定时推送和消息发送异常会以合并聊天记录展示操作、可读原因和脱敏诊断，管理员通知继续保留。私聊错误留在私聊，同类后台故障5分钟内限频；发送结果不明时不会自动重发原消息。见[错误报告说明](docs/ERROR_REPORTING.md)。

QQ Bot 启动后会私发管理员启动通知，附当前实际部署的前8位 commit hash、含时区的提交时间和完整提交说明；无法读取 Git 版本信息时会明确标注，不影响正常启动。

服务器安全更新采用发行版官方软件源，目前由管理员手动检查和执行；凌晨更新与自动重启已暂停，保留开机服务健康检查。更新前检查服务并保存私有恢复点，内核补丁须核对重启后实际版本；Nginx 与独立 Node 运行时分别沿用官方稳定版和当前主版本。维护前也检查代理的磁盘配置，避免旧进程正常但重启失败。手动更新、空间清理与排查入口见[主机安全维护](deployment/server_modules/SECURITY_UPDATES.md)。

AI 聊天中设置的消息触发规则暂仅限原设置者修改、暂停、恢复或删除，管理员也不能代他人操作；同群成员仍可查看本群规则。现有规则沿用原设置者记录，无需重新创建。

AI 聊天数据库查询支持额外成员（`extra_useridlist` / `extra_roleidlist` / `extra_namenick`）。可以按已配置昵称询问表现、装备和同局关系，也能查询已保存的个人快照与底蕴评估。没有本人战绩时，使用已归档同局详情中的本人数据；统计仅覆盖已收录样本，不代表该成员的全部战绩。详见 [AI 聊天说明](docs/manual/chapters/chat.md)。

AI SQL 支持 PostgreSQL 的布尔聚合、数组包含及交集判断；参数使用不加引号的 `:name` 或 `%(name)s`，并与 `params` 一一对应。查询先复用轻量战绩与身份事实，再按需读取详情，减少阵容分析的重复扫描；单条 SQL 默认30秒，可配置为1至60秒。查询授权和只读校验保持独立，详见 [数据库查询说明](src/glorybond/storage/sql/CHAT_AGENT.md)。

DeepSeek 聊天将每轮变化的运行统计与稳定上下文分开，改善 prefix cache 复用；完整历史、推理与工具结果仍会保留。缓存收益体现在输入费用和延迟，实际命中量可在运行记录中查看。

聊天输入按本轮提问、引用及媒体组织，个人直接历史与群聊背景统一去重、按完整轮次和各自预算选取。模型只接收本轮需要的身份记录和相关记忆，较早资料继续通过已有工具查询；完整归档保留。主模型确定详细正文，合适短答直接沿用，较长回复只生成简版，避免再次改写对象和判断。说明见[角色与回复风格](docs/manual/chapters/roles.md)与[上下文组装](src/glorybond/agent/README.md#聊天上下文组装)。

新增群消息归档保留原生 @ 对象的 QQ、归档时可获取的群名片及昵称快照，只有 @ 的消息和 @全体成员也会保存。历史正文显示可读的 @ 标记，名字读取失败时保留 QQ；旧归档缺失的信息不自动补写。说明见[群聊背景查询](docs/manual/chapters/history.md)。

AI 聊天可以读文档，也可以按需看群里的近期图片。回复一份群文件并问 `@机器人 总结这份 PDF，列出依据`，或直接问 `@机器人 刚才群里的截图写了什么？`。本地聊天网页通过“＋ 附件”选择文档。格式、大小和使用范围见[文件与群聊图片说明](docs/manual/chapters/vision.md)。

AI 识图支持独立的火山方舟豆包端点，本次配置采用 Seed 2.1 Lite（`doubao-seed-2-1-lite-260915`）。QQ 与本地 Web 共享 `VisionAPI`，有图片的请求及图片追问使用视觉模型，纯文字与回复整理沿用当前文字模型。API Key 仍保存在 `.env`，需先在方舟控制台开通对应模型；申请入口、配置与验证方法见[豆包识图接入](src/glorybond/agent/README.md#豆包识图接入)。

王者官方客户端请求目前统一停用（`PlayerClient.enabled=false`）。`#在线` 恢复营地方式，战绩查询只请求营地，普通英雄查询保留原有统计并跳过客户端图片和资料。显式 `#客户端` 命令及后台官方客户端登录操作提示已停用；营地和 NapCat 登录正常使用。已有客户端凭据、绑定和历史记录保留。配置及边界见[玩家客户端部署说明](deployment/README.md#王者玩家客户端)，验证方式见[开发说明](docs/DEVELOPMENT.md#checks-and-manuals)。

营地的战绩、个人资料、英雄数据、榜单和观战查询统一使用独立的 [hok-camp-client SDK](https://github.com/Raysance/hok-camp-client)，原有 Bot 命令和网页入口继续使用。SDK 另提供本局胜率、经济/经验走势与完整对局回顾接口，可返回玩家位置、事件和双方经济记录，供业务按需接入；本次未新增 Bot 命令或网页回放。连续请求按客户端实例至少间隔5秒，失败不自动重试；登录态由 SDK 保存和更新，项目只传私有会话文件路径。接入接口与维护边界见[营地 SDK 接入](docs/camp-sdk.md)。

## 📖 总览

GloryBond 是 QQ 群里的王者荣耀助手，支持战绩查询、英雄数据、实力评估和职业赛事查询，也能聊天、看图、画图、记住偏好和安排提醒。

- **固定功能**：发送 `#` + 命令，如 `#我的战绩`、`#今日英雄`。
- **智能对话**：直接 @机器人 后提问，如 `@机器人 分析一下我最近的表现`。
- **查询他人**：战绩、分析等命令中的“我”，可换成已登记的玩家昵称。
- **使用条件**：消息入口暂不因 QQ 未绑定而回复 `access denied` 或记录拒绝日志；主动禁用名单仍生效。游戏功能沿用各自的账号登记及数据可见要求。

下文 `@机器人` 表示在 QQ 中实际选中机器人进行 @。图片为公开示例，实际数据以查询结果为准。

## 🎮 核心功能

### 一、战绩查询

#### 1. 排行榜查询

**触发方式**：`#排行` / `#排名`

**功能说明**：

- 返回浅色战报图片，展示游戏头像与游戏昵称、巅峰净上分、排位净上星、当日把数和距最近收录对局的天、时、分、秒；按当日把数排序，未游玩成员也保留。
- 沿用原有营地战绩刷新与归档；未打间隔只读已保存的全模式对局。头像使用 URL 缓存，7天内直接复用，地址变化时重新下载，刷新失败保留可用旧缓存。
- 战绩隐藏、查询失败和未知值分别显示，不把缺失算成零。成功时直接发送图片，不再附文字榜单、问候、AI点评和旧排行网页。

新增 `#多久没打了`（也支持 `#多久没打排名` / `#多久没打排行`，兼容全角 `＃`）：只读已保存战绩，按距最近收录对局的时间从长到短排列，包含所有已收录模式、不限赛季，不请求营地或官方客户端。没有有效记录及最近归档隐藏的账号不参与排名；采集缺档不能证明没有游玩，间隔也不代表离线时长。

每日23:30推送复用同一张战报图片，后续代表局仍按原顺序发送。

#### 2. 个人战绩查询

**触发方式**：`#` + 玩家昵称 + `的战绩` + 可选日期

**使用示例**：

```text
#我的战绩
#我昨天的战绩
#昵称的战绩-8
#昵称的战绩7-14
```

依次查询今天、昨天、8天前、7至14天前的战绩。

玩家隐藏战绩时，个人战绩页仍展示其已公开的头像、游戏昵称、段位、等级和区服。

**返回内容**：各模式场次、胜负、平均评分、段位变化和战绩网页；有可用详情时附最近一局的摘要及图片。

<img src="resources/demo/battle_detail.png" width="400" alt="单局战绩长图示例">

#### 3. 在线状态与巅峰排名

```text
#在线
#巅峰排名
```

- **在线**：查看已登记玩家的王者状态，以及已绑定 Steam 账号正在玩的游戏。
- **巅峰排名**：查看已收录的历史排名，不代表当前实时名次。

#### 4. 历史对局条件查询

**触发方式**：`#查询` + 条件描述

**功能说明**：按玩家、英雄、模式、日期、胜负、同局玩家、KDA、评分、时长及各类表现比较筛选。共鸣之战按模式筛选，可与MVP等成就条件组合。

**使用示例**：

```text
#查询我和昵称一起玩的排位赛中我评分更高的对局
#查询我最近7天用安琪拉获胜的对局
```

**返回内容**：匹配对局的胜率、评分等统计。只有1局时返回详情和图片，多局返回列表网页；没有匹配时会说明。

### 二、英雄数据

#### 1. 英雄战力查询

**触发方式**：`#` + 玩家昵称 + `的战力`

```text
#我的战力
#昵称的战力
```

返回高战力英雄、战力值及可用的地区排名。

#### 2. 单玩家单英雄数据

**触发方式**：`#` + 玩家昵称 + `的` + 英雄名

```text
#我的安琪拉
#昵称的露娜
```

返回本赛季英雄资料及近期表现，包括战力、胜负、胜率、评分、MVP 和 KDA 等。

#### 3. 单玩家多英雄数据

```text
#我的英雄
#昵称的英雄
#我本赛季的英雄
```

查看常用英雄、胜率榜和评分榜。常用英雄汇总默认近30天；可指定本赛季。

#### 4. 多玩家单英雄数据

```text
#群u的安琪拉
```

查看已登记玩家使用该英雄的场次、胜率、评分、模式分布和玩家榜单。

#### 5. 多玩家多英雄数据

```text
#群u的英雄
```

查看已登记玩家的英雄汇总，包括出场、胜率和评分榜。`群u` 表示已登记的玩家集合。

#### 6. 今日英雄

**触发方式**：`#今日英雄`

根据个人数据推荐英雄，附相关图片和推荐理由。仅支持本人，当日保留同一推荐结果。

### 四、智能对话

#### 1. 普通聊天

**触发方式**：直接 @机器人 后输入内容

```text
@机器人 分析一下我最近的表现
@机器人 和上周相比呢？
@机器人 把依据也展开给我看
```

支持连续追问、查询战绩和数据分析。群聊回复会 @ 本次提问者，通常简短回答；需要完整内容时可要求展开。内容较多时，可以按完整意思分几条发送。

在群聊或私聊中撤回触发 AI 的那条消息，机器人收到撤回通知后会停止该轮准备和 ReAct 执行，不再发送后续最终回复或失败提示。已开始的运行保留取消记录；已发送的消息和已提交的外部操作不会因此撤销，其他提问及已有后台任务继续运行。

AI 任务报错时也会发送同一份聊天记录转发，保留本次原话与思考轨迹链接，详细回复的位置改为错误摘要，说明错误类型、原因、失败阶段及已耗时；随后发送原有简短失败提示。摘要根据已记录的错误生成，不额外请求模型。

#### 2. 看图、引用与群聊背景

```text
（附图片）@机器人 这张图里有什么？
（引用消息）@机器人 这句话是什么意思？
@机器人 刚才大家在聊什么？
```

- 可以理解图片、截图及可读取的动态表情；动画取部分画面理解。
- 可以读取本次明确引用的文字和图片，引用中的命令不会执行。
- 可以按需查当前群的近期讨论或相关历史发言。

#### 3. 记忆管理

```text
@机器人 记住我喜欢玩中路

@机器人 你记得我的哪些偏好？
@机器人 忘记我喜欢安琪拉这条偏好
#清除记忆
```

保存本人稳定偏好，支持查看、纠正和删除。明确纠正也可更新记忆，不必每次说“记住”。普通群聊不会每天自动提炼成个人画像。

`#清除记忆` 清除本人长期事实及当前对话上下文；不删除群聊原始记录、运行记录、角色偏好或其他会话。正文加入 `nomem` 可让本次对话不使用长期记忆。

#### 4. 角色与回复风格

```text
@机器人 有哪些角色可以选？
@机器人 切换成通用助手
@机器人 联网添加《原神》的安柏并选用
@机器人 以后回复简短一点，少用表情
```

支持选择角色、添加新角色和保存个人表达偏好。角色选择仅影响本人的回复。
未扮演角色时，通用助手默认尖锐直白、有主见，抓住核心矛盾，分析机制、约束与因果链。日常闲聊、玩梗和按外观辨认自然接话，已接受近似判断就继续话题，不纠缠无关细节或反复追加来源声明；要求查证、影响重要判断或实际操作时保留必要核验。个人表达偏好仍可调整语气。
角色模式也遵守同一互动约定。对回复口吻的调侃会自然接话或简短自嘲，调整不合适的旧说法，不借角色嘴硬替自己辩护或责怪用户。
主模型的完整正文作为详细版及本人直接历史保存。已有合适短答直接交付；较长正文的简版从原文压缩，整理阶段不重写详细正文或增加事实、归因与确定性。
聊天按需要选择工具，当前资料足够时直接回答；群聊背景区分发言者、原回复对象和引用关系，读取范围固定在本次消息的时间。数据 worker 的启动信息报告实际查询编译模式。工具与数据查询约定见 [AI 查询说明](src/glorybond/storage/sql/CHAT_AGENT.md)。
追问保留详细答案中的资料，查询后继续交付原先要求的成品，不把写作改成图表或只说“稍后查询”。主执行阶段支持推理与自动工具调用，群聊短版仍由独立表达阶段生成。
历史统计只覆盖已归档记录，缺档不代表之后没有对局或没有上线。
“今天/本周/本月”按北京时间实际开局时间统计；明确查询业务日战报时才沿用业务日期。个人、队友与装备分析共用比赛模式和时间范围，空结果不自动改换时期。记忆保存本人原话来源，旧助手推断不能变成已核实事实；提醒的计划、执行与实际发送分别核对。

AI 可读取当前请求使用的模型、已报告的 token 用量和执行进度，日常回复默认省略这些统计。需要了解时可直接询问，完整调用信息保存在运行记录中。

## 📞 常见问题

**Q：为什么没有回复？**

A：检查是否实际 @ 到机器人、命令是否带 `#`，以及账号是否被主动禁用。QQ 未绑定不会触发入口拒绝；游戏功能仍需满足对应账号要求。休眠、维护或冷却也会影响回复。引用中的 @ 不会单独触发聊天。

**Q：为什么查不到我的战绩？**

A：确认游戏账号已登记、王者营地已授权且战绩可见。未收录、条件不匹配或查询失败时，也可能查不到。

**Q：如何查看多天的数据？**

A：例如 `#我的战绩7-14` 查看7至14天前，`#查询我最近7天的排位赛` 按条件查对局。

**Q：底蕴和预言能判断谁一定赢吗？**

A：只能作为双方实力参考。授权、资料完整性及临场发挥都会影响结果。

**Q：订阅和偏好会因机器人重启丢失吗？**

A：成功保存的订阅和长期偏好会保留。定时任务在服务停止期间无法按时执行，恢复后不集中补发错过的消息。

**Q：订阅后会私聊通知我吗？**

A：B站和 X 自动推送发送到已接入的推送群；本人可随时用命令查看最新内容。

**Q：能查其他群的聊天吗？**

A：群内只查当前群；普通私聊不能读取群聊。管理员私聊可查询已授权群。

**Q：网页聊天与 QQ 一样吗？**

A：网页可以聊天、看图、查资料、分析、画图和安排提醒；QQ 命令、实时群成员资料及戳一戳需要在 QQ 使用。
