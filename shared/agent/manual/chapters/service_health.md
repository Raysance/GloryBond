# 服务连通性检查

管理员可在群聊或私聊发送 `##health` 或 `##连通性检查`，也支持全角井号。必须单独发送完整命令；普通用户不能执行。这是 QQ 命令 handler，不是 AI 聊天工具。

检查 Redis DB0、PostgreSQL 业务和聊天只读身份、QQ/OneBot、已启动的 Agent 两条 worker 连接、Bot 网页产物依赖的本机 Web、HOK 公网健康接口，以及模型、搜索、王者、天元之弈、B站、Steam、X、AI 日报、KPL、QQ头像和 Emoji 图片 CDN。systemd 只读取配置中显式列出的 Bot 进程及必要依赖，不枚举全机服务、定时器或 socket，不检查个人网站、OAuth、SSH、Actions runner 等无关服务。

模型采用只读模型列表检查凭据及所配聊天模型是否可见；Steam、B站、数据库和 QQ 采用最小读操作。没有合适轻量业务接口的服务采用 HEAD，仅检查 HTTP 可达。图片生成、收费搜索、模型生成、游戏登录状态、X Cookie 有效性和完整业务流程不会由这些轻量结果推断。不会发送测试消息、创建任务、重启服务或修改业务数据。

报告以一份聊天记录转发回复到发起命令的群或私聊，固定分成两个节点。第一条是有问题或待确认的服务，包含异常、注意、仅可达、跳过及未完成项；第二条是没问题的服务，仅包含检查正常项。空组仍保留说明，每项保留原因和耗时。仅可达或跳过不代表已确认故障，也不当作业务正常。401/403、限流、缺少凭据、模型列表没有目标模型、接口结构未知及健康端点降级会明确提示；响应正文、密钥、连接串及网址不进入回复。systemd active 只表示进程状态，端口及业务接口结果另列。开发用的非 systemd 主机会显示跳过。

默认并发 6 项，每项 4 秒，总检查预算 30 秒，配置位于 `ServiceHealth`。超时仍汇总已完成结果，并标记未完成项；重复请求同时只能运行一次。可以在配置中调整必需 systemd unit 和本机健康端点，迁移主机时应同步修改。检查仅由管理员手动触发，已有定时消息不受影响。
