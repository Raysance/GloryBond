# 服务连通性检查

管理员可在群聊或私聊发送 `##health` 或 `##连通性检查`，也支持全角井号。必须单独发送完整命令；普通用户不能执行。这是 QQ 命令 handler，不是 AI 聊天工具。

检查 Redis DB0、PostgreSQL 业务和聊天只读身份、QQ/OneBot、已启动的 Agent 两条 worker 连接、本机 Web、个人网站与 OAuth、HOK 公网健康接口，以及模型、搜索、王者、天元之弈、B站、Steam、X、AI 日报、KPL、QQ头像和 Emoji 图片 CDN。服务器还检查配置中的 systemd 服务，并枚举本机其他运行中、失败或正在切换状态的服务、定时器和 socket。未运行且不在配置中的服务不会被自动认定为应当运行。

模型采用只读模型列表检查凭据及所配聊天模型是否可见；Steam、B站、数据库和 QQ 采用最小读操作。没有合适轻量业务接口的服务采用 HEAD，仅检查 HTTP 可达。图片生成、收费搜索、模型生成、游戏登录状态、X Cookie 有效性和完整业务流程不会由这些轻量结果推断。不会发送测试消息、创建任务、重启服务或修改业务数据。

报告区分“正常”“可达”“注意”“异常”“跳过”，并给出各项原因和耗时。401/403、限流、缺少凭据、模型列表没有目标模型、接口结构未知及健康端点降级会明确提示；响应正文、密钥、连接串及网址不进入回复。systemd active 只表示进程状态，端口及业务接口结果另列。开发用的非 systemd 主机会显示跳过。

默认并发 6 项，每项 4 秒，总检查预算 30 秒，配置位于 `ServiceHealth`。超时仍汇总已完成结果，并标记未完成项；重复请求同时只能运行一次。可以在配置中调整必需 systemd unit 和本机健康端点，迁移主机时应同步修改。检查仅由管理员手动触发，已有定时消息不受影响。
