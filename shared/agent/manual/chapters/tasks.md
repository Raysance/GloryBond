# 定时提醒与多次消息

### 用途

延迟发送提醒、按周期发送指定次数，或者定时查询后给你结果。

### 使用示例

```text
@机器人 10分钟后提醒我休息
@机器人 明天21:30提醒我打王者
@机器人 从明天起每天21:30 @全体成员打王者，共365次
@机器人 每隔10秒给我发一条消息，发三次
@机器人 每小时查一次指定话题的最新消息，共查两次
@机器人 十分钟后查一下大家的在线状态
@机器人 每小时给我查一次最近底蕴，共三次
@机器人 十分钟后发一张最新英雄梯度图
@机器人 每小时在群里 @示例玩家65 提醒他别卷了，共两次
@机器人 十分钟后在群里说“休息一下”，不要 @ 任何人
@机器人 十分钟后私发给示例玩家65，提醒他休息
@机器人 看看我在这个会话里安排的任务
@机器人 看看本群有哪些定时任务，分别是谁设置的
引用一条定时消息后 @机器人 这条是谁设置的？
引用一条定时消息后 @机器人 取消这条消息对应的定时任务
@机器人 取消刚才的提醒任务
```

### 返回内容与注意事项

先收到创建结果，再在约定时间收到消息。固定文字提醒与需要查询的任务都可安排；支持的最短周期为1秒。支持具体日期时间或延迟两种首次时间方式，二选一。指定“几点”时提交具体日期时间和时区，由程序计算；“多久后”使用延迟。首次时间须在未来一年内，已过期的具体时间会拒绝创建，不会自动改到明天。确认回复以实际保存的首次时间为准。两种首次时间均未指定的周期任务会等待一个周期后开始。

QQ AI 聊天和定时查询也支持调用已开放的现有业务功能，包括在线状态、玩家单日战报、巅峰排名、英雄战力与统计、英雄梯度、本人今日英雄、评分趋势与观战截图、底蕴、游戏时长及代表局。可以直接说明要查什么、何时查询，得到文字或图片。本人今日英雄沿用本人身份和每日限制。只有登记且当前用户有权限的功能可执行，不能任意调用内部函数；本地网页暂未接入这组业务功能。

同一轮相同参数的业务查询只实际执行一次，反复请求复用已有结果；查询失败或取消后不会反复重放。业务函数不能重新进入 AI 或调度入口，后台任务也不能再创建子任务。需要重复查询时应在创建任务时说明周期和次数，或在前台调整原安排。业务执行繁忙或超时会明确报告，不能把超时当作查询成功。

任务发往创建时绑定的当前会话。群提醒可以指定真正 @ 当前群中的其他成员、@全体成员，也可以明确不 @；“提醒全群”会选择原生 @全体成员，仅说“在群里发送”不代表 @全体。@全体成员的实际效果受机器人群权限和 QQ 额度限制；创建前确认的选择会随任务保存，重启后仍沿用。不能借此改成私发或发往其他群。同群成员都可以查看和取消发往本群的任务，列表会显示创建者；创建者和提醒 @ 的对象可能不是同一人。其他群、私聊及网页任务相互独立，私聊和网页仍只限当前会话。取消应以成功结果为准，只阻止后续触发，已入发送队列的消息可能仍会送达。服务停止时不会按时执行；恢复后错过的时间点不会集中补发，异常重启也不能保证通知绝不重复。本地网页任务需要本地服务运行。

引用机器人发出的定时消息后，可以询问是谁设置的，或者要求取消对应任务。机器人按当前群和真实 QQ 消息 ID 查询发送回执关联，默认保留30天；旧消息或没有关联记录时会说明无法确认，不按文案或 @ 对象猜测。

如果明确要求定时私发给群成员，机器人可以在到时执行独立私发动作，先校验目标仍属于绑定群，再等待 QQ 发送回执；原会话只确认状态，不重复私发正文。已有普通定时消息不会自动变成私发。私发仍受 QQ 好友关系和临时会话限制，失败或结果不确定时不会盲目重发。

同一次提问也可以分批回答，无需创建定时任务。信息较多、多个问题、详细步骤或对象对比时，可以先收到结论，再收到依据和后续步骤；也可以直接说“内容多的话分几条发，讲清楚就行”。每条按完整意思组织，保持角色语气与个人偏好，避免逐句刷屏；用户要求一条或简短时优先遵守。已发送的正文不会在最终回复中整段重发，并与最后一条回复一起保存在当前会话上下文中，便于追问。分批是否发生由模型结合问题判断，并非每个回答都会拆分。
