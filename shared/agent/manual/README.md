# 手册维护

`handbook.md` 是人工阅读入口，`catalog.json` 是检索树，`chapters/` 是按功能独立维护的用户说明。目录不保存正文副本，计算公式、服务来源、默认范围、样本门槛和边界条件写进对应主题文件，不用模型临时从代码猜测。

## 节点约定

树形顺序为 `manual → 类别 → 功能 → 具体主题`。节点 ID 稳定、唯一；调整标题无需更换 ID。`parent` 决定层级，不另存 children 避免两处不一致。分支只保存 `summary`、`keywords`、`tools`、`code`；正文只能挂在叶节点。

叶节点 `document.path` 必须在本目录的 `chapters/` 下。`heading=null` 表示一个独立主题文件；指定 heading 时按文件中的二级/三级标题读取，不把同文件其他主题一并返回。建议重要规则单独建文件；原有功能用法可在一个功能文件中分小节。索引摘要只概括该主题，关键词补充用户常见说法。

每个功能及其叶节点的 `code` 标明核对该功能的 Python `path` 和 `symbol`，如 `Class.method` 或函数内的嵌套函数。公式可用 `focus` 声明该函数内唯一赋值变量，AST 定位随行号变化自动刷新。不要填配置、密钥、日志、任意目录或大段不相关入口函数。文件/符号重命名时同步更新目录。

叶节点省略 `code` / `tools` 时继承最近父节点的关联位置，功能共用的引用只维护一次；精确主题可覆盖为自己的引用，显式空列表表示没有关联。返回的节点卡片总会展开有效代码位置，模型不需要自行推断继承关系。

## 查询约定

- `browse` 浏览当前节点下一层；`search` 只搜索当前节点的子节点。无匹配时可浏览目录换说法，不回退成全局全文读取。
- 选中叶节点后 `read`，有 `next_offset` 时连续读取剩余页。目录和正文使用独立预算，图片、图片 alt 和媒体链接不进入索引。
- 已读完整说明仍缺少具体事实时才 `code`，填写 `fallback_reason`，仅核对同一节点的代码位置。程序校验本轮读取状态和版本，不凭模型声称“读过了”。源码缺失或片段截断必须说明，不能当成已证实的功能。

## 更新流程

1. 修改功能时更新其用法、计算口径、默认范围、样本及失败/权限边界；可变默认值与项目配置同步核对。服务来源可以写公开供应商/API和初始模型，不写凭据。QQ命令与AI工具、生成图片与理解图片等能力应分清。
2. 新增说明先在 `chapters/` 建正文，再给 `catalog.json` 增加叶节点及父级、关键词、相关工具和代码位置；同步人工导航。不要把无关信息塞到已有主题来避免建节点。
3. 执行 `local_debugger/.venv/bin/python scripts/validate_agent_manual.py` 检查目录、全部正文小节和代码符号；执行 `local_debugger/.venv/bin/python -m unittest tests.test_bot_manual` 验证分层检索及代码兜底。
4. 发布后重启外部适配器加载正文和索引。代码摘录来自实际目标主机；本地新文档与远程旧代码不同版本时，保留版本差异与不可用标记。

预算在 `catalog.json#limits` 独立维护，当前目录和正文各最多3000字符；每次3个节点，上限5个。代码总量最多6000字符、单片段2000字符、最多4个引用。启动加载是适配器内部动作，模型每次只收到本次选择的节点。
