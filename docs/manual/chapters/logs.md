# 查看完整回复与运行记录

### 怎么用

QQ每次最终回复都会发两条：先发送详细版聊天记录转发，再直接发送简略版，私聊和群聊一致。详细转发开头是本次用户原话，中间是完整正文和图表，最后一条是本轮chat-trace思考轨迹网页链接。第二条方便快速看结论，群聊的@放在简略版上。想继续展开某一部分时，可以说“把上面的依据展开”“给我完整结果”。

转发末条的chat-trace链接复用已经留存的本轮运行记录，任何人持有效链接都可以直接打开，无需登录；此前已经分享的有效链接同样适用。管理员还可以进入 Web 控制台的“AI 运行记录”，按时间查看、搜索问题摘要或 QQ、筛选群号与状态，再打开完整轨迹调试；记录默认保留7天、最多1000条。简略回复保持正文和图表，普通来源链接不受影响。本地网页可以切换查看详细内容与群聊回复，也可以展开执行过程和查看 token用量。

也可以直接引用机器人的简略回复或详细转发，问“这次为什么这么慢，工具链、token、费用分别是多少”。AI 可调用 `read_run_history` 按实际QQ发送回执查到那一次运行；没有引用时可以问本人上一次对话，或提供已知的运行编号。查询由模型按需选择，与网页、图片等工具平级。消息关联从功能上线后保存7天；早期消息和过期关联会明确说明无法定位，不会用相似回复替代。本群成员可查询本群运行，私聊与本地网页仅限本人对应会话。

### 会看到什么

详细版保留依据、数据和来源；执行过程可以展示实际工具调用、结果和错误。token用量是接口报告的统计，未知或未完成的用量会说明。只有接口实际返回的思考字段才会展示，不会制造思考过程。

历史运行查询工具返回模型、状态、每轮及每个工具的时长、用量覆盖和费用；并发工具分别显示工作时间与整批经过的时间。识图和音视频工具的新用量也会计入，缓存复用不重复计算。价格估算附日期、来源和必要的范围，接口报告金额单独保留；未知费用不算成零，也不将估算宣称为实际扣费。工具不返回原始系统提示词、思考正文、工具参数或完整结果，运行时长不包括QQ排队和送达耗时。

记录可以帮助调试，但查看功能指南不会把聊天日志或原始图片读出来。群聊归档和 AI对话记录是两回事；在本地网页聊天不会被伪装成 QQ群里的原始发言。
