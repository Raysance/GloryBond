# AI 聊天运行记录

机器人每次最终回复会将文字、图表和运行记录链接合并为一条消息。多张 Python 图表默认等比合为一张总图，页面仍保留原图入口。

引用一条 QQ 消息后向机器人提问，它会读取被引用消息的文字作为本次分析资料。已撤回或无法读取的消息会标明不可用；图片、语音和视频只识别消息类型，不会自动识别其中内容。引用内容不会自动写入长期记忆。

点击回复末尾的「运行记录」可以查看对话和执行过程。宽屏左侧采用本地 agent studio 的浅色聊天样式，包含用户气泡、角色名称、助手正文，以及已保存的「详细内容 / 群聊回复」两个版本；群聊回复可以直接复制。阶段性消息按发送顺序保留。点击 token 数可查看本轮和各次请求的输入、输出、总量及缓存用量，缺失数据会标为未记录。执行过程默认折叠，点击其中的步骤会打开右侧对应详情；图表可以放大查看。窄屏通过顶部「对话 / 轨迹」切换。

右侧保留 DeepSeek Harness 的轨迹查看方式：按轮次选择步骤，再切换概述、参数、结果、Schema 和计时。顶部三条时间带分别显示输入、模型请求和工具执行，支持搜索、折叠轮次和导出脱敏记录。每轮均单独列出真实的 System Prompt、Context Injection 和全部 Tool Definitions；上下文以实际 provider 请求为准，缺少 provider payload 时使用 NBot 在调用适配器前保存的模型可见快照。运行记录同时展示记忆和群聊工具的调用参数、返回原文、上下文与错误详情；每轮助手步骤的「参数 / 结果」保留完整请求和响应 JSON payload，正文不会省略，headers 不保存，API 密钥等凭据脱敏。结束原因、token 用量、错误阶段和异常原因链也会保留。旧记录只有已有问答时仍可阅读，不会补造角色名、双版本回复、思考过程或用量。

记录链接默认保留 7 天，持有链接即可查看；图表原图按现有产物清理周期保留。链接过期后显示过期提示。若发布记录暂时失败，机器人仍会发送已完成的答案，并提示链接不可用。

默认一次聊天最多执行 10 轮工具循环和 16 次工具调用，必要时追加一次最终回答请求；空正文最多再补试一次，因此最多 12 次模型请求，仍为空时保留已有资料并返回兜底说明；不会把每轮过程分别发到群里。图表源图最多 4 张。

每次具有可信群范围的 chat 都会在回答前强制模型直接调用 `search_chat_history`。模型先从原问题提取人物、对象、事件、动作、别称或同义表达，生成 2–6 个去重且不重复原问题的互补 query；程序再附加原问题，对当前群全部用户的全部已保存发言执行多 query BM25，并用 RRF 融合结果。管理员私聊以同样方式覆盖所有已保存群，普通私聊不会跨入未知群范围。询问某位玩家最近在说什么时，机器人仍可按发言时间读取近期消息；玩家别名由程序解析为 QQ 号，营地 ID 不会被当作 QQ 号检索。

管理员登录 Web 控制台后，可进入「系统健康诊断」手动验证 chat 运行链路。公开 `/health` 与 GitHub Actions 发布流程仍只做快速服务检查，不请求模型；深度诊断仅在点击后执行，覆盖当前 NBot 进程是否对应已部署代码和凭据、DB0 对话/记忆/角色读取、PostgreSQL 群聊归档、模型只读 SQL 账号、BM25/RRF 历史检索、工具渐进披露、绘图隔离依赖、DeepSeek 普通回复及工具续传，以及 OpenRouter 经 Clash 的真实联网搜索。页面只显示脱敏结果和各阶段耗时。一次深度诊断约产生 4 次小型外部请求，同一 Web 进程内不允许并发重复执行。
