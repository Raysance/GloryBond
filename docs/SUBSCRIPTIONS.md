## B站 UP 视频

| 操作 | 命令 |
| --- | --- |
| 订阅 UP | `#订阅B站 罗翔` |
| 查看本人订阅 | `#我的订阅` |
| 查看最新视频 | `#最新视频` |
| 取消指定 UP | `#取消订阅 罗翔` |
| 仅有一个订阅时取消 | `#取消订阅` |

- 支持订阅多个 UP，按名称搜索匹配；遇到同名时需补充信息。
- 按账号跟踪，UP 改名后继续有效。
- 订阅成功时返回最新视频，之后默认每5分钟检查新视频。
- 分享、订阅推送和最新视频查询直接发送原生 QQ 视频，不再发送封面加跳转链接；订阅成功的确认文字单独发送。
- `#最新视频` 查询本人所有订阅 UP 的最新公开视频。
- 多个订阅时，取消需指定 UP 名称或账号 ID，空命令会提示选择。

群聊或私聊直接发送 `bilibili.com` 视频地址、`b23.tv` / `bili2233.cn` 短链、BV/av号及原生 JSON/XML 分享卡即可触发，无需命令前缀。支持 `?p=2` 等分P地址；一次最多处理3个视频，连续重复分享会短期去重。只检查本条消息自身，不递归读取引用消息或合并转发。主动禁用名单、休眠和维修限制继续生效。

### 下载与维护

下载依赖 [Parser Lite 独立版](https://github.com/sokoko-org/nonebot-plugin-parser-lite/tree/standalone)，当前固定 `2e171fc41fd938aac585512ac3d54c0b1771d473`（`1.4.2rc5`，2026-11-26）。依赖只负责 B站取流、下载和合并，QQ 路由、权限、缓存与发送仍由本项目管理。更新固定提交后需验证取流、音视频合并及宿主测试，不在服务启动时自动更新依赖。

服务器需安装 FFmpeg，Bot 与 NapCat 必须能读取同一视频文件路径。当前同机部署直接使用 `file://`，不把视频放入公开网页目录。视频缓存在 `HOK_DATA_DIR/bili_videos/`，成功文件复用24小时，后续下载清理过期文件；完成文件缓存预算1 GiB，同时最多2个下载，过忙会明确提示。每个任务使用私有临时目录，失败或超时清理临时文件，超时同时结束下载及 FFmpeg 子进程。

原生视频消息单独允许180秒等待 QQ 上传回执；超时记为结果未确认，沿用统一出口的不重放策略，普通文字和图片消息的超时设置不变。

可在已有 `config.yaml` 添加以下配置；省略时采用这些默认值，无需新增私有配置才能启用。

```yaml
BiliVideo:
  enabled: true
  max_size_mb: 90
  timeout_seconds: 180
  max_height: 480
  target_size_mb_per_5min: 10
  max_output_size_mb: 20
```

`max_size_mb` 是源文件上限，单位 MiB，允许1至500；`timeout_seconds` 覆盖下载、合并和压缩，允许30至300秒。默认优先取480P AVC源，再按实际时长检查成片预算。`max_height` 可选480或720，保持原比例、不放大低分辨率源；需要压缩时输出 H.264 与 AAC 声音，音频48 kbps、帧率最高30。

`target_size_mb_per_5min` 是需要压缩时的参考目标，默认每5分钟约10 MB，允许1至50；兼容旧配置名 `max_size_mb_per_5min`。`max_output_size_mb` 是单个视频的发送上限，默认20 MB，允许1至100；这里 MB 均为十进制，20 MB 即20,000,000字节。符合分辨率、编码且不超过发送上限的源直接复用，避免无谓转码。其他源通过 FFmpeg 按时长和发送上限中较小的预算压缩，输出略超参考目标也可以发送；仅实际超过单个视频上限才再次压缩，仍超限则不发送。缓存键包含全部压缩设置，修改后不会复用旧的超限成片。

实际画质、付费/地区限制由 B站决定。暂不提供 B站登录流程；不可下载或超限时仅返回简短原因，不发送旧的图文链接卡片。自动订阅失败保留待推视频，后续轮询可继续尝试；一个视频失败不阻断其他视频。消息入队后沿用统一出口的回执和不重放策略，入队不代表 QQ 已确认送达。

已有消息触发规则仍能按订阅 UP 和视频标题筛选；标题保留在可信事件元数据中，不额外发送文字卡片。

## X 账号

| 操作 | 命令 |
| --- | --- |
| 按用户名订阅 | `#订阅X @XDevelopers` |
| 按主页链接订阅 | `#订阅X https://x.com/XDevelopers` |
| 查看本人订阅 | `#我的X订阅` |
| 查看最新内容 | `#X最新内容` |
| 取消指定账号 | `#取消X订阅 @XDevelopers` |

### 账号与推送

- 支持多个账号，用户名不区分大小写；也支持 twitter.com 主页链接。
- 使用账号用户名或主页链接，不支持按显示昵称搜索。
- 默认只推原创公开帖，不推转帖和账号自己的回复。
- 首次订阅返回最新帖预览，自动推送不补旧帖。
- 默认每5分钟检查，新帖发布至少5分钟后推送，等待回复积累。
- 同一账号被多人订阅时，只推送一次。
- 未指定取消对象时，只有本人恰好订阅一个账号才直接取消。

### 消息内容

```text
作者名 · 发帖时间（多久前）
中文内容预览
[图卡，长内容可有多张]
原帖链接
```

时间采用原帖发布时间，按北京时间显示到秒。中文预览默认最多280字符，超出后提示“全文见图”。

图卡包含完整正文、可读取配图、热门回复和英文内容的中文译文。中文译文优先展示，英文原文保留；长内容分页，不按预览长度截断。视频只提供预览，需打开原帖观看。

### 热门回复与翻译

热门回复从可见公开回复中采样，默认最多读取100条，按点赞数选取5条，也可能包含楼中楼。卡片会标注采样范围，不代表 X 全量热门排名。

无回复、读取失败或翻译失败时会明确标注。翻译失败保留原文；回复与点赞为生成时的快照，不持续更新已发送图卡。

### 网页读取维护

读取使用 `.env` 中的 `HOK_X_AUTH_TOKEN`、`HOK_X_CT0` 与现有 `Proxy.clash_url`，不调用开发者付费 API。新版 x-web 首页通过内联入口加载模块，程序静态读取当前公开脚本，发现 transaction 签名索引、Relay 查询 ID 与提供变量；不会执行网页 JavaScript。公开脚本按内容版本 URL 在进程内限量缓存，登录页面、Cookie 和帖子响应不进入该缓存。旧网页加载方式仍兼容。

新版原创查询为 `UserOriginalsTimeline`，含回复查询为 `UserTweets`，详情查询为 `TweetDetail`。`XSubscriptions.web_query_ids` 在新版中按这些实际操作名覆盖查询 ID；旧网页仍使用原操作名，`web_features` 仅用于旧网页协议。接口 ID 覆盖不能替代返回结构适配。时间线按发布时间排序读取，支持新版正文、长文、媒体、回复和点赞字段。

订阅记录继续绑定稳定账号 ID，读取前通过受限的 X 主页跳转获取当前用户名，账号改名无需重新订阅。引用帖、置顶帖和广告不作为独立新帖；失败时不推进游标，避免漏推。

错误提示区分网络/代理连接失败、读取超时、会话不可用及网页适配变化。首页 HTTP 200 只说明页面可达，不能证明帖子接口可用。适配回归应同时检查账号、原创/含回复时间线、详情及分页，不能只检查首页。会话错误时才核对登录状态与 Cookie；脚本映射、查询或结构错误需更新适配代码。

## 接收范围与常见问题

**Q：推送发到哪里？**

A：B站与 X 自动通知发往已接入的推送群，订阅记录按本人保存。主动查询结果回复到当前会话。

**Q：重启后需要重新订阅吗？**

A：不需要，成功保存的订阅会保留。

**Q：为什么暂时没有新消息？**

A：可能还未发布新内容、未到检查时间，或外部服务暂时不可用。X 还需等待发帖后的回复积累时间；会话失效时需管理员恢复服务。

**Q：可以直接 @机器人 要求订阅吗？**

A：请使用上面的 `#` 命令。聊天可以询问用法，订阅成功以命令回复为准。

**Q：两类订阅会互相覆盖吗？**

A：不会。B站与 X 独立管理，`#我的订阅` 和 `#最新视频` 仍用于 B站。
